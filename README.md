## 项目背景

「智游北京・AI 旅行管家」是一款面向北京旅游市场的智能路线规划 Web 应用：用户输入旅行需求或选择主题标签（文化古迹 / 亲子研学等），调用 **DeepSeek API** 生成个性化一日游行程，前端结合**高德地图 JS API** 完成地图标注、路线规划与导航跳转，并支持景点收藏、足迹打卡、门票 / 酒店 / 套餐预订。该产品获 2026 年「挑战杯」首都大学生创业计划竞赛北京市三等奖，**我是项目负责人**，本仓库 `frontend/` 目录即产品前端代码（API 密钥已脱敏为占位符，填入自己的 key 即可运行完整功能）。

赛后复盘时我们发现产品在商业化论证方面有所欠缺，于是我以自己的产品为载体，独立补做了一次完整的产品数据分析，并进一步设计了 A/B 实验与可视化看板，形成「产品 → 分析 → 实验 → 监控」的完整闭环。分析聚焦三个问题：**用户从哪来、在哪流失、钱该往哪投**。

## 数据说明

产品处于内测阶段、未全量上线，故本项目数据为**基于产品功能逻辑构造的模拟埋点数据**（生成规则复刻真实业务规律：渠道间转化差异、周末效应、留存衰减、冲动型渠道高退款等）。分析方法论、指标体系、SQL 与 Python 实现均为真实完成，可直接迁移至真实业务数据。

| 表 | 规模 | 说明 |
| --- | --- | --- |
| `users.csv` | 8,000 行 | 用户维度：注册时间、获客渠道、城市线级、设备、年龄 |
| `events.csv` | 499,623 行 | 埋点事件：会话 ID、用户 ID、时间、事件名、渠道 |
| `orders.csv` | 13,644 行 | 订单：产品类型、金额、支付 / 退款状态、渠道 |

**事件链路**：`app_launch` → `ai_plan`（发起 AI 规划）→ `view_spot`（看详情）→ `add_favorite`（收藏）→ `create_order` → `pay_order`

> 仓库 `data_sample/` 里就是上表中的**全量数据**，clone 后按下方「如何复现」操作，即可原样跑出 README 中的所有结论数字。

## 指标体系

* **业务目标（OSM）**：净 GMV 的可持续增长，按 AARRR 拆解到获客 / 激活 / 留存 / 变现 / 传播五环节
* **北极星指标**：周活跃规划用户（WAU-Plan）——"成功生成一条行程" 是用户感知价值的核心瞬间，前置于收藏、预订与分享，且可被产品 / 运营 / 市场动作直接撬动

## 分析模块与核心结论

| 模块 | 方法 | 关键发现 |
| --- | --- | --- |
| 增长监控 | 北极星指标 + LAG 周环比 | 增长由投放驱动，投放收缩即回落，自然增长引擎未建立 |
| 漏斗诊断 | 会话级 AARRR 漏斗 | 整体转化 5.4%；「规划→详情」流失 41% 是最大杠杆点 |
| 渠道评估 | 分渠道漏斗 + 净 GMV / 退款率 | 抖音 "量大利薄"（转化 1.9%、退款率 11.1%）；微信裂变质优（转化 11.6%，约 6 倍于抖音） |
| 留存分析 | 注册周 Cohort | 次留 52.4% / 7 留 32.0% / 30 留 13.3%，留存随时间快速衰减 |
| 用户分层 | RFM（NTILE 三分位） | 「重要唤回用户」333 人、人均 ¥803，是单客杠杆最高人群 |
| 交易分析 | 产品结构 + LEAD 复购 | 酒店以 34.7% 订单量贡献 53.7% 净 GMV；首单 30 日复购率 43.4% |

## 业务结论与行动建议

> 一句话回答开头的三个问题：
>
> **用户主要来自付费投放渠道（抖音量最大但质量最差）；流失集中在「规划→详情」的决策环节；经营重心应从付费拉新转向高价值用户运营与交叉销售。**

| # | 业务结论 | 数据依据 | 行动建议 |
| - | --- | --- | --- |
| 1 | 增长依赖付费投放，自然增长引擎尚未建立 | 北极星指标 WAU-Plan 随投放收缩回落，自然渠道未形成自增长 | 短期以投放维持周活规模、防止回落；中期将 AI 行程沉淀为可分享的行程卡片，依托微信裂变建立自增长通道 |
| 2 | 最大流失发生在用户看到方案之前 | 整体转化 5.4%，「规划→详情」一步流失 41%，是最大杠杆点 | 优化规划结果页，前置展示行程亮点与一键收藏；对发起规划但未查看详情的用户做次日召回（已设计 A/B 实验验证，见 `04_AB实验设计.md`） |
| 3 | 投放预算应向微信裂变倾斜，收缩抖音信息流 | 微信转化 11.6%（约 6 倍于抖音）；抖音转化仅 1.9%、退款率 11.1%，量大利薄 | 将投放预算由抖音转移至微信裂变；抖音保留少量品牌曝光，仅投放高意向素材 |
| 4 | 留存断点在首周之后，用户未形成周期性使用习惯 | 次留 52.4% / 7 留 32.0% / 30 留 13.3%，D7 至 D30 衰减近六成 | 以周为周期推送「周末主题路线」等二次出行灵感，引导用户从单次规划走向周期性使用 |
| 5 | 变现应聚焦高价值用户，单客杠杆最高 | 「重要唤回用户」333 人、人均消费 ¥803 | 对 333 名沉睡高价值用户做定向召回（短信 / 推送触达 + 专属优惠券），作为预算优先投入项 |
| 6 | 酒店是营收主力，门票是获客入口 | 酒店以 34.7% 订单量贡献 53.7% 净 GMV；首单 30 日复购率 43.4% | 在门票支付成功页推荐周边酒店，搭建「门票→酒店」交叉销售路径；推出「门票 + 酒店」打包套餐提升客单 |

## 技术栈

* **前端产品**：原生 HTML / JavaScript 单页应用，接入 DeepSeek API（AI 行程生成）与高德地图 JS API（地图展示 / 路线规划）
* **MySQL 8.0**：CTE、窗口函数、条件聚合、留存 Cohort 取数
* **Python (pandas)**：数据清洗、漏斗 / 留存 / 渠道分析
* **Tableau Public**：双轴、计算字段、参考线、Cohort 热力图，多视图仪表板搭建与发布
* **A/B 测试**：两比例 z 检验、样本量估算、护栏指标与决策规则设计

## 项目亮点

1. **从业务问题出发，而非从代码出发**：先定 "净 GMV 增长" 这个目标、拆出北极星指标和 AARRR 口径，再动手写 SQL/Python，把获客到变现五个环节一次跑通
2. **每个结论都落到业务策略上**：抖音渠道转化 1.9%、退款率 11.1%，建议减投；微信裂变转化 11.6%，预算向它倾斜；对 333 名 "重要唤回用户"（人均 ¥803）做定向召回；用 "门票→酒店" 搭交叉销售阶梯
3. **数字经得起复算**：核心指标用 SQL 和 Python 两套代码独立实现、口径对齐，分析结果可复现校验
4. **形成完整数据闭环**：不止于出报告——分析发现的问题（41% 流失）有 A/B 实验方案承接验证，结论有 Tableau 看板承接监控，「发现问题 → 验证方案 → 持续监控」全链路打通
